# 要件・設計 Q&A

## 運用

- 要件・設計に関する質問と回答をこの文書に追記する。
- 複数の質問にまとめて回答してよい。回答は対応する Q&A ID を示す。
- 回答が設計・要件に反映されたら、状態を「反映済み」にする。
- 新しい質問は次の連番 ID で追加する。

## Q&A

### QA-001: 応用WBの構成

- 状態: 反映済み
- 質問: キャラクターごとの応用WBをどのように表現するか。
- 回答: 各キャラクターに3属性があり、属性の内訳はキャラクターごとに異なる。各属性の最大レベルは25。
- 反映: 各キャラクターのマスター定義にWB属性を3件登録し、利用者データには属性ごとの現在レベルを保存する。値域と初期値の意味は QA-005 に従う。

### QA-002: ゲーム定義データの管理場所と形式

- 状態: 反映済み
- 質問: キャラクター名、スキル名、WB内訳、装備種別などをどこで管理するか。
- 回答: GitHub リポジトリ内にデータベースのように保存する。CSV など形式は扱いやすいものでよい。
- 設計判断: キャラクターごとに構成が異なる関連データを表現しやすく、ブラウザで直接扱える JSON を採用する案とする。マスターはリポジトリでバージョン管理し、アプリからは読み取り専用とする。利用者個人の所持・育成記録は引き続き localStorage に保存する。

### QA-003: 初期マスターの収録範囲

- 状態: 反映済み
- 質問: 初回公開時点で、プレイアブルキャラクターと衣装違いをすべて収録するか、まずは一部を収録して順次追加するか。
- 回答: プロトタイプ時点では全キャラクターでなくてもよいが、公開時点では現時点での衣装違いを含む全キャラクターを対象とする。
- 反映: プロトタイプでは一部データで開発し、公開前に全キャラクターと衣装違いをマスターへ収録する。

### QA-004: マスター未収録キャラクター

- 状態: 反映済み
- 質問: マスターにまだ登録されていないキャラクターも、アプリ上で名前だけ手入力して記録できるようにするか。それともマスター登録後に選択可能とするか。
- 回答: 全キャラクターをマスターへ登録する方針のため、手入力は不要。
- 反映: 所持キャラクターはマスターから選択する。未登録キャラクター用の自由入力は設けない。

### QA-005: 応用WBのLv0と未入力

- 状態: 反映済み
- 質問: 各属性のレベルは 0〜25 とし、0 を未開放として扱うか。それとも未入力と 0 を区別するか。
- 回答: WBに未開放という概念は基本的にない。キャラクターが☆5以上であれば育成可能で、初期値は0、最大値は25。
- 反映: 各属性の値域は0〜25とする。0は初期値であり「未開放」を意味しない。アプリのデータ上は未入力と0を区別し、未入力は別状態として扱う。
