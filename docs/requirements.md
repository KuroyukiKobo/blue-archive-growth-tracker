# ブルーアーカイブ育成状況管理 Web アプリ 要件定義

## 1. 文書情報

- 文書の状態: 初版要件
- 対象: GitHub Pages で公開する個人向け Web アプリ
- 目的: 初版の開発範囲と、後続の設計で決定する事項を整理する

## 2. 背景と目的

ブルーアーカイブで所持しているキャラクターと、それぞれの育成状況を個人で記録・確認できるようにする。キャラクター名、スキル名、応用WBの内訳、装備の種類などのゲーム定義データは、GitHub リポジトリ内の静的マスターデータとして管理する。プロトタイプでは一部キャラクターのマスターで開発できるが、公開時点では現時点の全キャラクターと衣装違いを収録する。

## 3. 対象利用者

- 自分の所持キャラクターと育成状況を管理したい個人
- アカウント登録やサーバー同期を必要としない利用者

## 4. 初版の範囲

### 4.1 対象機能

- マスターデータから所持キャラクターを選択して追加し、一覧表示、育成状況の編集、削除を行う
- キャラクター名、スキル名、応用WBの内訳、装備の種類などを GitHub リポジトリ内のデータファイルで管理する
- アプリはマスターデータを参照する。マスターデータの追加・修正はリポジトリの変更として行う
- 各キャラクターの育成状況の記録
- 入力内容のブラウザ内保存と、再訪時の読み込み
- 登録キャラクターが1人の場合も複数人の場合も利用できる

### 4.2 育成状況の対象

育成状況は、ゲーム内でキャラクターごとに管理する育成要素の現在値を扱う。目標値や育成計画は初版では管理しない。少なくとも以下を対象とする。

- レベル
- レアリティ（★）
- スキル
- 応用WB（能力開放に用いるWB）
- 絆

「すべての育成状況を記録したい」という要望に沿い、装備、固有武器、愛用品などの育成要素も対象に含める。全キャラクターは★5まで育成可能で、★5で固有武器が解放される。装備はキャラクターごとの3枠に記録し、各枠はキャラクターLv1、10、20で順次解放される。愛用品は対象キャラクターのみ記録する。

応用WBはキャラクターごとに異なる3属性で構成し、各属性のレベルは0〜25とする。0は初期値であり未開放を意味しない。能力解放はキャラクターLv90かつ★5で利用可能となる。どの属性を持つかはキャラクターごとのマスターデータで定義する。

キャラクターレベルの上限は先生レベルとする。先生レベルは利用者全体の設定値として管理する。絆ランクの上限はレアリティに応じ、★1〜2で10、★3で20、★4で30、★5で100とする。

### 4.3 初版の対象外

- アカウント登録、ログイン、クラウド保存、端末間同期
- アプリ画面からのマスターデータ編集・リポジトリへの書き戻し
- CSV のインポートおよびエクスポート
- 複数利用者でのデータ共有
- 育成目標値や育成計画の管理

## 5. 機能要件

要件 ID は設計・テスト工程で参照する。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-01 | 利用者はマスターデータからキャラクターを選択して所持キャラクターとして登録できる | 必須 |
| FR-02 | 利用者は登録済みキャラクターの一覧を確認できる | 必須 |
| FR-03 | 利用者はキャラクターの育成状況の現在値を入力・更新できる | 必須 |
| FR-04 | 育成状況にはレベル、レアリティ（★）、スキル、応用WB、絆を記録できる。キャラクターレベルは先生レベル以下、絆ランク上限はレアリティに応じて扱い、応用WBはマスターで定義された3属性それぞれの現在レベルを0〜25で扱う | 必須 |
| FR-05 | 装備3枠それぞれのTierとTier内レベル、固有武器の★段階とレベル、対象キャラクターの愛用品Tier（T1/T2）を記録できる | 必須 |
| FR-06 | 利用者は登録済みキャラクターの情報を編集・削除できる | 必須 |
| FR-07 | キャラクターおよび育成状況はブラウザ内に保存され、ページを再読み込みしても保持される | 必須 |
| FR-08 | CSV 出力を後続機能として追加できるよう、キャラクターと育成状況を一貫したデータ単位で管理する | 将来対応 |
| FR-09 | アプリはリポジトリに含まれるマスターデータからキャラクター、スキル、応用WB属性、装備種別を読み込む | 必須 |
| FR-10 | 利用者は先生レベルを設定でき、キャラクターレベルの入力上限に反映される | 必須 |

## 6. 非機能要件・制約

- 公開先は GitHub Pages とし、初版は静的 Web アプリとして動作する。
- 初版ではアプリケーションサーバーや外部データベースを必要としない。
- マスターデータは GitHub リポジトリでバージョン管理し、GitHub Pages から静的ファイルとして配信する。アプリ実行中にリポジトリへ書き込まない。
- ゲーム定義のマスターデータと、利用者個人の所持・育成データは分離する。後者はブラウザのローカルストレージに保存する。
- 保存先にはブラウザのローカルストレージを使用する。これは一時的な HTTP キャッシュとは異なる。
- 保存データはブラウザおよび端末ごとに分かれ、別端末との同期は行わない。
- ブラウザのサイトデータ消去などにより保存内容が失われる可能性がある。この制約を利用者が把握できるようにする。
- 将来の CSV 出力や育成項目の追加に備え、保存データの構造を拡張可能にする。

## 7. 受け入れ条件

- リポジトリのマスターデータからキャラクターを選択して登録できる。
- 1人以上のキャラクターを登録し、それぞれの情報を一覧で確認できる。
- レベル、レアリティ、スキル、応用WB、絆をキャラクターごとに記録して更新できる。
- 応用WBはキャラクターごとに定義された3属性を表示し、それぞれLv0〜25を記録できる。Lv0は初期値として扱い、能力解放はキャラクターLv90かつ★5で利用可能とする。
- キャラクターレベルは設定された先生レベルを超えて登録できない。
- 先生レベルを更新すると、キャラクターレベルの入力上限が更新される。
- キャラクターのレアリティは★1〜5で記録し、装備3枠の解放レベルはそれぞれLv1、10、20とする。
- 各装備枠の装備TierとTier内レベルを別々に記録できる。
- 固有武器はキャラクターが★5で解放され、★段階とレベルを別々に記録できる。
- 愛用品はマスターに定義されたキャラクターのみ表示し、T1/T2を記録できる。
- 絆ランクの上限は、★1〜2で10、★3で20、★4で30、★5で100として扱う。
- 育成状況は現在値として記録し、目標値は初版で扱わない。
- 登録内容を編集・削除できる。
- ページを再読み込みした後も、登録内容と育成状況がブラウザ内に残っている。
- マスターデータが静的ファイルとしてアプリとともに配信され、主要な利用フローが成立する。

## 8. 設計工程で確定する事項

- レベル、スキル、装備、固有武器のゲーム更新ごとの値域をマスターへ正確に反映する
- マスターJSONとlocalStorageデータの最終スキーマ、および将来の形式変更時の移行方法
- CSV の列、文字コード、エクスポート対象と、インポートを対応するか
- 削除時の確認方法およびデータ消失に関する画面上の案内
- プロトタイプ用マスターは一部キャラクターでよいが、公開前に全キャラクターと衣装違いを収録し、欠落・重複を検証する
